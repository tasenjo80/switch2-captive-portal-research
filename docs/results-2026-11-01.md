# Results — 2026-11-01

Sanitized session summary. Raw logs, exact heap addresses/offsets, and
screenshots are private.

## Setup

- Console: one Switch 2, firmware 23.0.1.
- Test AP: isolated, no WAN; PC served DNS/HTTP and the local portal.
- Console state: the last successful online check was roughly 12 hours before
  the first session; the applet opened normally before the tests.
- The sessions were inside the 24-hour window. This is **not** a 24-hour gate
  result.

## Entry

- The local portal launched `WifiWebAuthApplet` and loaded the controlled page.
- Applet User-Agent:
  `Mozilla/5.0 (Nintendo Switch; WifiWebAuthApplet) AppleWebKit/613.0
  (KHTML, like Gecko) NF/7.0.3.12.11 NintendoBrowser/5.2.0.55481`
- WebKit compatibility string: `AppleWebKit/613.0`.
- The applet stayed open for more than 11 minutes on the first entry and
  re-opened twice without a reboot.
- The page reported `BigInt`, `FinalizationRegistry`, `WeakRef`,
  `structuredClone`, `Gamepad`, `IntersectionObserver`, and `ResizeObserver`
  as available. `WebAssembly`, `WebGL`, `WebGL2`, `WebGPU`,
  `SharedArrayBuffer`, `Atomics`, `AudioContext`, `OffscreenCanvas`, and
  `requestIdleCallback` were unavailable.
- `FontFace` was available.

## Font environment

- Named local families (Nintendo font names, Helvetica, Arial, Times, Courier
  New) returned `NetworkError`.
- `systemfont` loaded synchronously and was used for the trigger.

## WebKit UAF

- A public `CSSFontFace` use-after-free path was reachable from the applet.
- Without a reclaim, the console crashed to the system error screen
  `2168-0002`.
- With a same-size `ArrayBuffer` reclaim spray, the applet stayed alive and
  the page reported both the UAF `FontFace` and the reclaimed buffer.
- A 4-byte read primitive and a self-address chain were confirmed in
  successful runs.
- The UAF path is timing-sensitive: later runs crashed during the
  trigger/reclaim or the read chain. The exact addresses, offsets, spray
  counts, and timings are private.

## File-path surfaces

The applet's WKC file procs were probed with benign inputs:

| Surface | Result |
| --- | --- |
| `file:///` link | No navigation; applet stayed on the page |
| `file:///` via script | No navigation |
| `download` link | Nothing happened |
| Blob download | `download` was ignored; the applet navigated to the `blob:` URL and rendered the text |
| `<input type="file">` | "The file selection is not supported" dialog, OK only |

These paths did not reach an `fs` write. The FS route from this applet is not
available through these web-controlled surfaces.

## Verified vs unverified

Verified on this one console/firmware:

- Local captive-portal entry and repeatable applet launch.
- The applet UA and WebKit 613.0 feature level.
- `systemfont` as the synchronous local font.
- Reachability of the `CSSFontFace` UAF; a no-reclaim trigger crashes the
  system.
- A same-size reclaim, a 4-byte read, and a self-address chain in successful
  runs.

Unverified or community-reported:

- The applet NPDM's `fsp-srv` permission and the `fs` overflow route.
- Stable write/ARW, `fsp-srv` calls, kernel access, CFW.
- The 24-hour gate behavior.
- Any permanent or untethered entry claim.

## Reliability note

The UAF path is not reliable enough to treat as a stable primitive. Repeated
crashes occurred; each crash is a system-level error screen, not a finding.
The console was powered off after a crash and checked for a normal boot before
the next attempt.

## Write primitive status

- A guarded self-address chain was repeatable in successful runs, and a fake
  CSSOM object was constructed without crashing the setter.
- The first write did not land in the intended buffer: the fake vector's
  capacity/size fields were ordered incorrectly, so the append expanded the
  vector and wrote to a new allocation.
- The private harness has the corrected field order; a retest is pending. The
  constrained 16-byte write is **not yet confirmed**.
- Exact offsets, addresses, spray counts, and the trigger code are withheld.
