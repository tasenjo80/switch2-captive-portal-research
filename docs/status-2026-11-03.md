# Status — 2026-11-03

Sanitized hardware status. Raw logs, addresses, offsets, payloads, and
screenshots are private.

## Scope

- One Switch 2, firmware **23.0.1**, one isolated test network.
- Same console as the 2026-11-01 and 2026-11-02 sessions.
- This is not a reliability claim across consoles, reboots, or firmware.

## Summary

- The applet's FS client was mapped further: a persistent storage/session
  object, a storage handle, its I/O buffer, and its size fields were
  identified through ARW.
- A controlled `localStorage` trigger and a cacheable HTTP-cache request did
  not use that storage buffer. The buffer kept its marker value and the
  storage object was unchanged.
- The FS request path/offset is thread-local and only exists during an FS
  call. The applet's data-only ARW cannot patch it during the synchronous
  call.
- The browser-only route cannot drive the native FS path/cache race described
  in the public ns2jb source. There are no `fsp-srv` calls, FS code execution,
  kernel access, or CFW.
- The renderer crashed after the probes completed (`2168-0002`); the probe
  data was captured. This is the known teardown behavior, not a new bug.

## Correction to earlier FS wording

- Earlier notes described a `GetEntryType` path-normalization overflow. The
  public ns2jb FS source indicates a path/cache race with a signed cache
  header, not a simple path-normalization overflow. Treat the older wording as
  unverified.
- This repository does not publish the ns2jb source, exploit code, or any
  payload; the source review is private.

## What this does not prove

- No FS code execution, no `fsp-srv` call, no kernel access, and no CFW.
- No applet-side PID1/FullPermission promotion.
- No permanent or untethered entry.
- The applet NPDM `fsp-srv` claim remains file-level/community. The FS client
  was observed at runtime; the NPDM itself was not independently dumped.
