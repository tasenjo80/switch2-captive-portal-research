# Status — 2026-11-02

Sanitized hardware status. Raw logs, addresses, offsets, payloads, and
screenshots are private.

## Scope

- One Switch 2, firmware **23.0.1**, one region, one isolated test network.
- Same console as the 2026-11-01 sessions.
- This is not a reliability claim across consoles, reboots, or firmware.

## Summary

- Full **16 MB arbitrary read/write** in the applet process was verified on
  hardware.
- The applet's FS client, mount table, WKC file procs, and session structures
  were mapped.
- A web-controlled FS path was not found. `fsp-srv`, `fs`, kernel access, and
  CFW remain unverified.
- An applet-side PID1/FullPermission promotion shortcut was evaluated and
  rejected: the server-side registry is outside the applet's ARW.
- A separate local-wireless (ldn) path was evaluated, found key-gated, and
  parked; it has no FS permissions in the public NPDM metadata.

## ARW

- The chain was reproduced across multiple runs with a public community WebKit
  chain for the same applet/firmware. That repository is now offline; its code
  is not published here and was not audited line-by-line.
- The chain uses the `CSSFontFace` use-after-free, same-size reclaim,
  self-address, constrained CSSOM write, and a dual typed-array read/write
  window.
- The 16 MB window is in the applet process. It is not kernel access.
- The chain is timing-sensitive. The renderer often dies after the run
  completes (`2168-0002`); one run survived the cleanup. Do not treat it as a
  stable primitive for repeated development.
- No exploit code, addresses, offsets, or payloads are published.

## FS mapping

- The FS client, mount table, WKC file procs, and session structures were read
  through ARW.
- `.bss` and the FS client page are writable; `.data` is read-only after init.
- The FS session manager is a self-referential slot array. The session object
  is state flags, not a path.
- The IPC/descriptor buffers contain allocator and type-name data; no
  persistent `sd:/`, cache, or `/..\` path was found.
- The FS request path is thread-local and only exists during an FS call.
- A `localStorage` trigger did not expose a path in the IPC buffers.
- A full `.bss` scan crashed after it started, likely on a guard page. The
  earlier 96 KB scan completed with no hits.
- No web-controlled path was found: `indexedDB` is null, cache names are
  fixed, and the download/file surfaces are blocked.

## PID1 promotion probe (negative)

- A public community bench proposed promoting the applet's FS session to PID 1
  by changing a saved PID/permission field.
- A read-only probe after full ARW matched the applet base and the `fsp-srv`
  string, but the proposed session object was client-side and the derived
  server registry address was outside the applet. The read crashed; no write
  was attempted.
- The PID1 permission registry lives in the `fsp-srv` server/KIP process, not
  in the WebKit applet. The applet's ARW cannot write it. The private
  SmileBASIC/ns2jb PID1 recipe required ARW in fs's heap, which this entry does
  not have.
- The community page also targeted the saved-PID lookup field, while
  FullPermission is a mask in the registry entry. That page's "real promotion
  not done" status is accurate.

## Chat/GameChat path (negative)

- Pressing **C** on the offline/90DNS console opened GameChat and returned
  error **2155-8007**.
- Nintendo support describes 2155-8007 as an online-feature/network error.
  GameChat requires a Nintendo Switch Online membership, persistent internet,
  a registered phone number, and the latest system update.
- The test console is offline/90DNS, has no NSO, and must not update for the
  WebKit work. The TURN/STUN path was never reached. The chat path is parked.
- Do not remove 90DNS or update the test console to force it. Revisiting this
  would require a disposable online console/account with NSO.

## LDN local-wireless path (negative, parked)

- A separate local-wireless (ldn) path was evaluated on 2026-11-02. The
  console's Nintendo ldn advertisement was captured and identified as LDN
  version 4 with AES-GCM.
- Decryption, joining, or peer emulation would require Switch 2/Ounce keys and
  game session material. No keys or second console were available.
- The only valid advertisement was the console's own; replaying it did not
  produce a visible room, likely because it is self-filtered.
- Public NPDM metadata lists `ldn` with `fsPermissions = 0`. Even code
  execution in `ldn` would not directly provide FS access.
- Bounded malformed action-frame and beacon-IE tests produced no freeze,
  reboot, or error.
- The path is not a viable FS route and is **parked** as of 2026-11-02. Raw
  captures, MAC addresses, and SSIDs remain private.

## Community payload review

- A newer public community payload pack was reviewed statically on 2026-11-02.
  Its own README labels it a **reachability/diagnostic probe, not a
  code-execution payload**.
- Its chain pages are diagnostics; no native/JOP path was found. Its launcher
  auto-runs a PID1 promotion probe that crashed the applet during read-only
  validation. It was not run as-is.
- The ARW portion was independently reproduced on hardware; the promotion
  claim was not.

## What this does not prove

- No `fsp-srv` call, no `fs` path-normalization trigger, no kernel access, and
  no CFW.
- No ldn exploit, ldn FS access, or ldn peer/join primitive.
- No permanent or untethered entry.
- No reliability claim across consoles, reboots, or firmware.
- The applet NPDM `fsp-srv` claim remains file-level/community. The FS client
  was observed at runtime; the NPDM itself was not independently dumped.

## Next steps

- Pause blind FS probing. The FS client is self-referential and the request
  path is thread-local; a fake object in the reclaim buffer is not a simple
  redirect.
- Do not pursue applet-side PID1 promotion: the permission registry is in the
  `fsp-srv` server process and is not writable from the applet's ARW.
- Reopen only with a firmware/applet dump for static analysis of the FS client
  and path builder, a second bug that yields a controllable FS parameter, or a
  released working FS chain for this applet.
- Leave the ldn path parked. Do not blind-fuzz it further: the advertisement is
  AES-GCM/Ounce-key-gated and ldn has no FS permissions in the public NPDM
  metadata.
- Keep the console offline and do not update.
- Monitor public research. Released code is used privately and is not
  republished here.
